#+title: Git-Annex

git-annex allows managing large files with git, without storing the file
contents in git.
It can sync, backup, and archive your data, offline and online.
Checksums and encryption keep your data safe and secure.
Bring the power and distributed nature of git to bear on your large files with
git-annex.
[fn:1] https://git-annex.branchable.com/

This is a compilation of the documentation provided at
[[https://git-annex.branchable.com/][https://git-annex.branchable.com/]].
The workflow is targeted at users who want to have a lot of control over their
repositories and synchronized content.
Different devices and machines with certain access privileges can be structured
in a decentralized fassion.

* Git-annex sync workflow

** Initialization
Creating a repository is very straightforward:

#+begin_src shell
  $ mkdir ~/annex
  $ cd ~/annex
  $ git init
  $ git annex init
#+end_src

Like any other git repository, git-annex repositories have remotes.
Let's start by adding a USB drive as a remote:

#+begin_src shell
  $ sudo mount /media/usb
  $ cd /media/usb
  $ git clone ~/annex
  $ cd annex
  $ git annex init "portable USB drive"
  $ git remote add laptop ~/annex
  $ cd ~/annex
  $ git remote add usbdrive /media/usb/annex
#+end_src

It can also be used with a git remote that is truly remote, a host
accessed by ssh:

#+begin_src shell
  $local: git clone <user@hostname>:/home/me/annex ~/annex
  $local: cd ~/annex
  $local: git annex init "my desktop"
#+end_src

or the other way:

#+begin_src shell
  # SSH to remote machine
  $remote: mkdir ~/annex
  $remote: cd ~/annex
  $remote: git init
  $remote: git annex init "my remote"
  # Switch back to local machine
  $local: git remote add <remote> <user@hostname>:/home/me/annex
  $local: git push -u <remote> <branch>
#+end_src

Merge ~synced/$currentbranch~, pull changes from specified remote and update
~synced/$currentbranch~:

#+begin_src shell
  cd </path/to/annex>
  git annex sync --content
#+end_src

This has to be done in all repositories in a decentralized fashion. To
avoid errors caused on repositories without access privileges to
remotes, merge the synced changes after the sync manually:

#+begin_src shell
  git annex merge
#+end_src

To modify or add files on such a repository, simply use:

#+begin_src shell
  git annex add .
  git commit
#+end_src

and the next ~sync~ operation from a repository with access to this
remote will grep the changes.

Alternatively, the following systemd services might be used to handle local,
tracked file modifications or merge synced content periodically with
=~/.config/systemd/user/git-annex-local-sync.service=:

#+begin_src conf
  [Unit]
  Description=Local git-annex commit and merge (no network)
  StartLimitIntervalSec=0
  
  [Service]
  Type=oneshot
  WorkingDirectory=%h/Documents
  ExecStart=/bin/bash -lc 'cd %h/Documents && /usr/bin/git-annex sync --no-pull --no-push'
#+end_src

and the corresponding timer =~/.config/systemd/user/git-annex-local-sync.timer=:

#+begin_src conf
  [Unit]
  Description=Run local git-annex sync periodically
  
  [Timer]
  OnBootSec=15min
  OnUnitActiveSec=15min
  Persistent=true
  
  [Install]
  WantedBy=timers.target 
#+end_src

** Configuration
Configure the settings of git-annex repositories:

#+begin_src shell
  # Require multiple copies of files on accessible remotes
  git annex numcopies 2
  # Exclude specific files in the preferred content section or make them mandatory in the required section
  git annex wanted here "include=*.flac and exclude=*.mp3 and exclude=*.m4a"
  git annex wanted here "include=share/*"
  # Alternatively edit the configuration file directly
  git annex vicfg
  # Check with
  git annex wanted --explain <remote>
  git annex find --want-get --not --in .
  git annex find --want-drop --in .
#+end_src

The next synchronization using:

#+begin_src shell
  git annex sync --content
#+end_src

or an explicit command with ~--auto~ like:

#+begin_src shell
  git annex get --auto
  git annex drop --auto
#+end_src

might update the preferred content of the repository in question based
on the availability of files on the remotes and the ~numcopies~
settings.

** Status information
Check the consistency of the repository:

#+begin_src shell
  time git annex fsck --fast | grep -A 10 -v "ok$"
  time git annex fsck | grep -A 10 -v "ok$"
#+end_src

Find non-distributed content on remote, i.e. possibly missing files:

#+begin_src shell
  git annex find --not --in=<remote> .
#+end_src

Check how much disk space is saved by unsynced or dropped files on the
current repository:

#+begin_src shell
  git annex info . --not --in here
#+end_src

** Clean-up
Remove an obsolete remote repository:

#+begin_src shell
  git annex move --from <remote>
  git annex dead <remote>
  git remote rm <remote>
  # Optional
  git annex forget --drop-dead
#+end_src
